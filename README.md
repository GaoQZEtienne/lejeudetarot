# 法式塔罗 · 四人牌桌

四位好友在同一个房间进行一局完整的法式塔罗牌。Python 服务端负责规则、计时与计分，浏览器只接收自己的手牌及公共信息。

## 本机打开

当前工作目录已经建立 `.venv` 并安装运行依赖。Windows 下双击 **`start-game.cmd`**，保持窗口打开，再访问：

**http://127.0.0.1:8080/**

也可在 PowerShell 中运行：

```powershell
.\.venv\Scripts\python.exe server.py
```

停止服务按 Ctrl+C。启动脚本不自动开启浏览器窗口。127.0.0.1 仅用于本机访问；异地好友需要下文的公网部署。

首次在另一台电脑安装（需要 Python 3.12 或以上）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

macOS/Linux 对应命令：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py
```

## 四人如何玩

1. 四位玩家打开**完全相同的地址**，输入不同昵称。第一位入座者是房主。
2. 四人都连接成功后，房主点击“开始游戏”。
3. 轮到你时选择“不叫”或更高合同：Prise ×1、Garde ×2、Jiedi ×3、Garde sans ×4、Garde contre ×6。不叫后退出本轮竞价；轮流加叫直到最高叫分者无人挑战，×6 立即定庄。四人均不叫则重发。
4. 选择 ×1/×2/×3 时底牌公开，庄家**只从原来 18 张手牌扣六张**，确认后收入全部底牌。×4/×6 不亮不换底牌，直接出牌。
5. 轮到你出牌时，点选亮起的合法牌，再点击“出牌”。灰牌不能选；需要出将时可以出小将。
6. 四张牌出齐展示 2 秒，由赢家先出下一墩。点击任意玩家昵称下的“已收 X 墩”直接查看该玩家的墩；也可查看上一墩、已公开底牌，庄家可随时回看自己的扣牌。
7. 第 18 墩结束后显示结算、各人本局与累计成绩。四人在线时房主可开始下一局。

同一浏览器普通窗口的多个标签页共享一个身份。要在一台电脑上模拟四人，请用四个独立浏览器配置文件或不同浏览器；同一隐私模式的多个窗口也可能共享存储，不能算四个独立身份。

## 人机补位与难度

人数不足时，房主可在等待开局或结算后点击空座位／“添加人机”，或点击“补齐人机”一次填满空位，支持 1 真人 + 3 人机、2 + 2、3 + 1。“移除”会释放对应人机座位，好友随后填写昵称即可入座。对局中不能增删或替换人机，结算后可调整；新入座者不继承原人机的积分或成就，上一局结算保留原参赛者。

房主可先选择新增人机的难度，也可在每位人机旁单独切换难度。默认“普通”，切换不清空该人机的积分与成就；局内不能改难度。

| 难度 | 策略 |
| --- | --- |
| 普通（默认） | 按手牌强度叫分；组合评估扣牌与收入底牌后的牌型；记录已出牌、缺门；保 Bout、保大将、给安全队友垫分，并考虑 Jiedi 末墩归属 |
| 进阶 | 在普通策略上采样符合已知信息的未知牌，用同一批样本比较候选叫牌／扣牌／出牌，模拟到结算后按最终合同分数选择 |

所有人机都只使用本人的手牌和公共信息，不共享私有手牌。普通版反应更快；进阶版每步搜索预算约 0.6 秒、最多 24 批样本，预算不足时使用普通策略，部分强制动作无需搜索。模拟在开服电脑的单个后台计算进程运行，不增加浏览器计算负担。无需 API Key、模型下载、GPU、训练或额外服务。

房主仅由真人担任，人机始终就绪但不算真人在线。所有真人断线或回到首页时，人机和牌局暂停；真人返回后恢复。局外最后一位真人主动离开会清空人机和房间。人机不投票；只有一位真人时可直接重开，至少两位真人时需两票同意。拒绝票达到剩余票数不足以通过时立即失败（4／3／2 位真人分别需要 3／2／1 票拒绝），失败仍冷却 120 秒。

策略接口、采样边界和复现测评的方法见 [BOT_INTERFACE.md](BOT_INTERFACE.md)。测评使用固定合同的配对牌局，不能代替真人实战对棋力的评估。

## 本房间规则

- 78 张，每人 18 张、底牌 6 张；六轮每人三张后放一张底牌，最后一张允许进入底牌。
- 随机首位叫牌/首攻者；逆时针行动。采用上述五档循环竞价，最高者为庄家。
- 先扣原手牌再收入底牌，六张底牌不得扣。R、将牌 1、21 和愚人禁扣；原手牌普通可扣花色不足六张，才补扣必要将牌并公开。
- 有首攻花色必须跟；缺门有将必须出将，**不强制压过桌面最大将牌**。
- 愚人可随时出；首出时下一张定花色。**包括末墩在内，始终保留给出牌者**；向收墩者补 0.5 分，同阵营内部补牌不改变阵营总分。保留原有愚人末墩大满贯例外。
- Prise、Garde 的扣牌计入庄家；Jiedi 的扣牌归最后一墩赢家，按其阵营计分。Garde sans 的隐藏底牌计入庄家，Garde contre 计入防守方。×4、×6 在最后一墩收完前所有人均看不到底牌；收完后在牌桌中央亮牌 **10 秒**，之后才计算分数、胜负与成就，更新累计积分。单人刷新不会重置亮牌计时。
- 0/1/2/3 个 Bout 的目标为 56/51/41/36 分，保留精确半分。每份分数 =（带胜负符号的基础分 ± 末将 10）× 合同倍数 ± 自然大满贯 200；基础分为 25 加牌分与目标的差值绝对值。庄家收付三份，防守方各一份。
- 检测 Petit sec 自动重发；不开放 Poignée 和宣告 Chelem。

最新需求见 [modi.md](modi.md)，原计划见 [PLANNING.md](PLANNING.md)。以上自定义规则优先于标准玩法；原始 `prompt.md` 保留不改。标准合同与计分参考 [FFT 规则](https://www.fftarot.fr/assets/documents/Reglement%20FFT.pdf)。

## 计时与返回牌局

牌桌右上角的“离开房间”按当前阶段处理：

- **局外（等待开局或结算后）**：清除入座身份，返回空白昵称表单，已入座人数减一。其他人或另一终端可以立即补位；原身份的其他标签页也会退出。房主离开时自动转交房主。新入座者累计成绩从零开始，上一局结算仍显示原参赛者。
- **局内（叫牌、扣牌、出牌及收墩）**：保留身份和手牌，返回带“返回我的座位”的首页。点击即可继续；其他已打开的牌桌标签页不受影响。

主动离开后刷新当前标签页仍停留在首页。局内可发起 **20 秒重开投票**，发起人计一票；每位真人每次只能选择一次同意或拒绝。两位真人同意即回到入座准备界面，保留四人座位但清空手牌、积分和成就计数，等待房主点击“开始游戏”；只有一位真人时可直接重开。拒绝票达到无法通过的数量，或到期不足所需同意票，视为失败；失败后 **120 秒冷却**。投票不暂停正常牌局计时，真人全部离线也不会暂停投票时限。

叫牌 30 秒，扣牌 90 秒，每次出牌 **60 秒**，最后 5 秒播放合成提示音。超时依次自动不叫、保留已确认的合法暂选并补足六张、随机出一张合法牌。未收到服务器确认的本地操作不算已提交。

刷新、短暂掉线后自动重连，不重置正常回合的时限。掉线真人会按原计时自动行动，不自动改成人机；真人全部离线时暂停，第一位恢复连接后重新给予当前阶段时限。房主在等待开局/结算阶段持续离线 30 秒，会把房主交给在线真人；当前对局不依赖房主在线。

身份凭据保存在浏览器本地，服务端只持有哈希。保持相同浏览器配置及相同网址（域名、协议和端口），不要清除该网址的存储。换设备或清除存储后不支持自动认领旧座位。

运行中的牌局快照保存在 `data/room.sqlite3`。**每次启动 Python 服务都会清空房间、积分和旧身份，所有人重新填写昵称**；浏览器刷新或短暂断线不会清空。局外四个人全部主动退出后也会清空积分与成就计数。运行时备份 SQLite 应使用备份接口。

需要换人或换终端时，在局外用原浏览器点击“离开房间”，然后从新终端填写昵称入座。若丢失原凭据并确定放弃整个房间，重启服务即可开始全新房间。

## 音乐与同桌互动

房间外无背景音乐。入座准备、叫分和扣牌循环播放 `musics/leschampselysee.mp3`；出牌及收墩循环播放 `musics/seikobeatclub.mp3`；结算播放 `musics/jiesuanyinyue.mp3`。倒计时提示音通过 Web Audio 本地合成，无需下载。声音开关同时控制背景音乐和提示音；浏览器限制自动播放时点击“开启声音”。

点击牌桌内“💬 快捷语”选择七条预设内容之一，消息以指向发言玩家的气泡在所有人的牌桌上显示 **5 秒**，不提供聊天记录，也不写入存档。点击其他玩家头像选择鲜花或鸡蛋，礼物从发送者飞向接收者，全房间同步展示。每位玩家发送间隔至少 1.5 秒；积分榜保留在手牌下方。

成就弹窗全房间可见，同种成就一次列出所有满足条件者；多个成就按顺序展示：

- 😰 “TA的连胜，我很怕”：连续三场获胜，按庄家/防守阵营胜负判定；失败或播报后重新计数。
- 😡 “不要，妨碍我”：两次当庄获胜；防守局不打断，当庄失败或播报后重新计数。
- 🐢 “玄武制胜”：连续五次有效发牌未叫分，包括四人全不叫的发牌；叫过分或播报后重新计数。
- 🙋 “我叫，我再叫！”：连续三次有效发牌叫过分；未叫或播报后重新计数。加叫多次仍只算一次发牌。

Petit sec 自动作废的发牌不参与叫分成就计数。换人不继承原玩家成就计数。

## 异地公网部署

### 免费方案：本机 + Tailscale Funnel

不必购买云服务器或域名。开服电脑安装 Tailscale、登录 Personal 套餐并按提示启用 Funnel 后，可把本机 8080 服务转发为 HTTPS 网站；朋友只需浏览器。玩牌期间电脑必须保持开机、联网且不休眠。

先用 `start-game.cmd` 启动游戏，再在 PowerShell 执行：

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' funnel --bg http://127.0.0.1:8080
& 'C:\Program Files\Tailscale\tailscale.exe' funnel status
```

`--bg` 使转发由 Tailscale 后台服务保持，不依赖命令窗口。它不会代替 Python 游戏服务，游戏服务窗口仍需保持运行。若提示 `foreground listener already exists for port 443`，先在原先运行 `tailscale funnel 8080` 的窗口按 Ctrl+C，再执行后台命令；不要同时启动两个相同端口的转发。

状态应列出 HTTPS 地址、`Funnel on` 和 `proxy http://127.0.0.1:8080`。当前配置地址为：

**https://kevingao.tailf99ed2.ts.net/**

首次配置时，[官方说明](https://tailscale.com/docs/features/tailscale-funnel#dns-propagation)指出公网 DNS 记录可能需要最多 10 分钟才能出现。能够在安装 Tailscale 的开服电脑访问，不代表外网已通：本机 MagicDNS 可能将域名解析成 `100.x` 私网地址。验证外网应使用未连接 Tailscale 的手机移动网络或好友设备。

排查顺序：本机 `http://127.0.0.1:8080/health` → `funnel status` → 公网 DNS → 外部 HTTPS/WSS。证书申请中或公网 DNS 尚无记录时，反复重置配置不能保证加快恢复。游戏的 8080 只需监听 `127.0.0.1`，无需为 Funnel 改成公网监听。

关闭这个公网入口：

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' funnel --https=443 off
```

Funnel 链接可被公网访问；本游戏仍按四位好友知道链接的设定运行。大家从一开始就使用同一个 HTTPS 地址入座，避免在 localhost 和公网域名之间切换造成座位凭据不共用。

### 可选方案：自有公网主机

需要一台持续运行、支持 WebSocket、具有持久磁盘的公网主机。只上传 HTML 到静态托管无法提供四人同步；Sites 的托管环境不能直接运行此 Python 进程。

可以把项目部署到已有 Linux 主机。Docker 示例：

```sh
docker build -t friends-tarot .
docker volume create tarot-data
docker run -d --name friends-tarot --restart unless-stopped \
  -p 127.0.0.1:8080:8080 \
  -v tarot-data:/app/data friends-tarot
```

在主机配置 Caddy 反向代理，将 [deploy/Caddyfile](deploy/Caddyfile) 中的 `tarot.example.com` 换成已指向该主机的真实域名。开放公网 80/443，由反向代理终止 HTTPS 并转发 WebSocket。四位玩家共享同一个 `https://你的域名/`。

运行一个服务进程/一个实例，不要配置多副本。SQLite 数据卷必须持久保存。本期按“只有四位好友知道链接”的需求，不提供账号体系或复杂访问管理；网址本身不是强身份验证。

非 Docker 运行可设置：

| 设置 | 默认 | 用途 |
| --- | --- | --- |
| `HOST` / `--host` | `127.0.0.1` | 监听地址；容器内设 `0.0.0.0` |
| `PORT` / `--port` | `8080` | 监听端口 |
| `TAROT_DB` | 项目 `data/room.sqlite3` | 持久化文件绝对路径 |

健康检查：`GET /health`。WebSocket：`/ws`。反向代理需保留 Host，允许长连接；浏览器会按 HTTPS 自动使用 WSS。昵称及每个动作在服务端校验，网页文件通过明确路由提供，数据库和源码不公开。

自有公网主机方案尚未部署，Docker/Caddy 示例尚未在实际主机验证。Funnel 已配置到上述域名；具体外网连通性须另外验证，不能仅依据本机测试判断。
